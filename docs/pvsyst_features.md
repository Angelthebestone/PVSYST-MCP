**Classification legend (used in every table):**

* **`DATA`** — **pure-data**: a file/plain-text artifact a headless tool can read **and** write directly.
* **`DATA(ro)`** — file exists and is plain text, but the docs say it is internal/proprietary and "should not be modified" (read-only in practice).
* **`CLI`** — reachable through `PVsystCLI.exe` (documented + shipped examples).
* **`GUI`** — **GUI-only**: no file, folder or CLI command backs it; only reachable through the PVsyst desktop UI.
* **`DATA+GUI`** / **`CLI+DATA`** — mixed.

**Important caveat quoted from S1 `getting-started/file-organisation/user-data/format-of-pvsyst-files`:**

> "Please note that the PVsyst file format is intended for internal use only. We provide no support regarding this format.
> These files contain structured information generated by PVsyst and should not be modified."

and

> "Up to PVsyst version 6.39, all PVsyst files (project, variant, weather data, etc.) were saved in binary format and it was
> not possible to read or edit those files. Starting with PVsyst version 6.40, the format of all PVsyst files has changed
> to text." … "Starting with PVsyst version 6.80, the encoding of all PVsyst files (*.PRJ, *.VCi, *.PAN, *.OND, etc.)
> has changed to UTF-8".

So *most* PVsyst artifacts are **plain text, UTF-8, `Key=Value` "PVObject" records** — mechanically writable — but
officially unsupported. This distinction is flagged per row.
